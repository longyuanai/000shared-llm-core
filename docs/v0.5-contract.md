## 7. 新增:MultiAgentOrchestrator(多 Agent 编排)

### 7.0 速查表(从 source 同步)

```
MultiAgentOrchestrator(router)                           # build with v0.1 router
orch.run(mission, [AgentRole.SCOUT, ...]) -> [Result]   # sequential, errors swallowed
AgentRole.{SCOUT,ANALYST,EXPLOITER,SYNTHESIZER,REVIEWER} # role enum (str)
MissionContext(task, inputs={})                          # scratchpad + metadata
AgentResult(role, output, error=None, latency_ms=0)      # one role's outcome
```

完整字段定义见 `src/shared_llm_core/multi_agent.py` 顶部 docstring + 下方章节。

### 7.1 设计动机

v0.1 阶段每个产品是**单体 LLM 调用**。v0.5 引入多 Agent 编排,允许:
- 一个 mission 拆给 N 个 role-based agent
- agent 间通过 shared scratchpad 通信
- 最终由 synthesizer agent 汇总

### 7.2 顶层导出

```python
from shared_llm_core import (
    MultiAgentOrchestrator,   # v0.5 新增:多 Agent 编排器
    AgentRole,                # 角色枚举
    AgentTask,                # 单个 agent 任务
    AgentResult,              # 单个 agent 结果
    MissionContext,           # 跨 agent 共享上下文
)
```

### 7.3 `AgentRole`

```python
class AgentRole(str, Enum):
    SCOUT = "scout"           # 信息搜集
    ANALYST = "analyst"       # 深度分析
    EXPLOITER = "exploiter"   # 攻击/验证
    SYNTHESIZER = "synthesizer"  # 汇总
    REVIEWER = "reviewer"     # 审核/质疑
```

### 7.4 `MultiAgentOrchestrator`

```python
class MultiAgentOrchestrator:
    def __init__(
        self,
        router: LLMRouter,
        *,
        max_concurrency: int = 4,
        scratchpad_size: int = 4096,  # tokens
    ) -> None: ...

    def run(
        self,
        mission: MissionContext,
        roles: Sequence[AgentRole],
    ) -> list[AgentResult]:
        """按 roles 顺序或并行调度 agent,返回每个 agent 的结果。

        - 第一个 agent 必须接收 mission.task 作为输入
        - 后续 agent 可通过 mission.scratchpad 读取前序结果
        - SYNTHESIZER 通常放最后
        """
```

### 7.5 `MissionContext`

```python
@dataclass(frozen=True)
class MissionContext:
    task: str                              # 任务描述(用户级)
    inputs: Mapping[str, Any]              # 输入数据
    scratchpad: tuple[str, ...] = ()       # 共享上下文(append-only)
    metadata: Mapping[str, Any] = field(default_factory=dict)
```

### 7.6 `AgentResult`

```python
@dataclass(frozen=True)
class AgentResult:
    role: AgentRole
    output: str                  # agent 文本输出
    findings: tuple[Finding, ...] = ()  # 统一 Finding(见 §9)
    latency_ms: int = 0
    error: str | None = None     # 失败时记录
```

### 7.7 行为契约

- 默认 `max_concurrency=4`,并发跑 agents
- `scratchpad` 是 tuple(append-only),任何 agent 写入都触发副本,不影响其他 agent 当前看到的内容
- agent 失败 → `AgentResult.error` 不为空,**不** raise(整体 mission 继续)
- `latency_ms` 包含 LLM 调用 + 解析 + scratchpad 写入

### 7.8 测试要求

- ≥ 10 个 test function,覆盖:角色调度、并发、scratchpad、失败处理、超时

## 8. 新增:RuleEngine(规则引擎)

### 8.0 速查表(从 source 同步)

```
class MyRule(Rule):                                      # subclass; set id + evaluate
    id = "my.product.find-foo"
    def evaluate(self, ctx: RuleContext) -> list[Finding]
RuleRegistry.default() -> RuleRegistry                   # builtin rules pre-loaded
RuleRegistry().register(rule) / .get(id) / .all()        # CRUD
RuleEngine(registry=None).evaluate(ctx) -> list[Finding] # errors → stderr, no raise
RuleEngine.evaluate(ctx, rule_ids=["x","y"])             # subset by id, in reg order
```

完整字段定义见 `src/shared_llm_core/rule_engine.py` 顶部 docstring + 下方章节。

### 8.1 设计动机

v0.1 各产品 detector 是**正则 + LLM**混合。v0.5 引入统一规则引擎:
- 规则是 Python `Rule` 子类,**纯函数**`(ctx) -> list[Finding]`
- 内置规则注册表,跨产品复用
- LLM 调用是规则触发的**下游动作**,不是规则本身

### 8.2 顶层导出

```python
from shared_llm_core import (
    RuleEngine,        # v0.5 新增:规则引擎
    Rule,              # 抽象规则类
    RuleContext,       # 规则输入上下文
    RuleRegistry,      # 全局规则注册表
)
```

### 8.3 `Rule` 抽象类

```python
class Rule(ABC):
    id: str                                # 唯一 ID,如 "001-correlate-bruteforce"
    severity_hint: Literal["low","medium","high","critical"] = "medium"

    @abstractmethod
    def evaluate(self, ctx: RuleContext) -> list[Finding]: ...

    def __repr__(self) -> str:
        return f"Rule({self.id})"
```

### 8.4 `RuleContext`

```python
@dataclass(frozen=True)
class RuleContext:
    subject: str                           # 规则作用对象(用户/IP/CVE/...)
    facts: Mapping[str, Any]               # 已知事实
    window: tuple[datetime, datetime] | None = None  # 时间窗
    related: tuple[Finding, ...] = ()      # 已发现的 Finding
```

### 8.5 `RuleEngine`

```python
class RuleEngine:
    def __init__(self, registry: RuleRegistry | None = None) -> None:
        self.registry = registry or RuleRegistry.default()

    def evaluate(
        self,
        ctx: RuleContext,
        *,
        rule_ids: Sequence[str] | None = None,  # None = 全部
    ) -> list[Finding]:
        """跑全部(或指定)规则,返回所有 Finding。

        规则失败 → 跳过该规则,记 stderr warning,不 raise
        """
```

### 8.6 `RuleRegistry`

```python
class RuleRegistry:
    def register(self, rule: Rule) -> None: ...
    def get(self, rule_id: str) -> Rule: ...
    def all(self) -> list[Rule]: ...

    @classmethod
    def default(cls) -> "RuleRegistry":
        """加载 shared_llm_core.rules.builtin 下的所有内置规则"""
```

### 8.7 行为契约

- 规则是**纯函数**(不修改 ctx,只读)
- 引擎**顺序**执行规则(可并行,但 v0.5 默认顺序,便于调试)
- `Finding.confidence` 必须在 [0.0, 1.0] 区间
- 失败规则**不影响**其他规则

### 8.8 测试要求

- ≥ 8 个 test function,覆盖:注册、查找、执行、并行、失败跳过

## 9. 新增:Finding 统一 schema

### 9.0 速查表(从 source 同步)

```
Finding(id="", source, severity, confidence, title)      # id auto-UUIDs if empty
Finding.to_dict() -> dict                                # stable field-order JSON
Finding.from_dict(data) -> Finding                       # tolerant of unknown keys
```

### 9.5 `Finding`

```python
@dataclass(frozen=True)
class Finding:
    id: str                                # 全局唯一 UUID
    source: FindingSource                  # 来源产品
    severity: FindingSeverity
    confidence: float                      # 0.0-1.0
    title: str                             # 一句话标题
    description: str = ""

    # 通用字段
    host: str | None = None                # 主机 / IP / 组件
    cve: str | None = None                 # CVE 编号
    ts: datetime | None = None             # 发现时间
    evidence: tuple[str, ...] = ()         # 证据链(原始文本/hex)

    # 关联
    related: tuple[str, ...] = ()          # 其他 Finding.id
    tags: frozenset[str] = frozenset()

    # 元数据
    metadata: Mapping[str, Any] = field(default_factory=dict)

    def to_dict(self) -> dict: ...          # JSON 序列化
    @classmethod
    def from_dict(cls, data: dict) -> "Finding": ...  # 反序列化
```

### 9.6 行为契约

- `id` 是 UUID4,生成时确保唯一
- `confidence < 0` 或 `> 1` → `ValueError`
- `to_dict()` 输出字段顺序**稳定**(按 dataclass 字段顺序)
- `from_dict()` 容忍未知字段(忽略,不抛错),保证向后兼容

### 9.7 测试要求

- ≥ 8 个 test function,覆盖:序列化、反序列化、字段校验、UUID 唯一性

### 10.0 速查表(从 source 同步)

## 15. v0.6 CLI Envelope 契约(产品 ↔ IntegrationGateway)

> **新增日期**: 2026-07-24
> **范围**: §10 `IntegrationGateway` 之外的**横向契约** —— 6 个产品 CLI 如何被 `JSONSubprocessAdapter` 调用、输出什么
> **实现位置**: `000shared-integration/src/shared_integration/adapters/base.py::JSONSubprocessAdapter`

### 15.1 设计动机

v0.5 §10 假定产品以 `ProductAdapter` 子类形式注入 gateway。v0.6 走**更轻的子进程路径** —— 每个产品暴露一个 CLI 子命令,gateway 用 `asyncio.create_subprocess_exec` 拉起来,读 JSON envelope,落进 `FindingRegistry`。

**好处**:6 个产品之间不需要互相 import,产品自己升级不影响 gateway。

### 15.2 调用约定(adapter → product CLI)

```
python -m <product_module> scan --input '<json_payload>' --json
```

- `python` 必须是**绝对路径**(Windows: `C:/Users/15072/AppData/Local/Programs/Python/Python314/python.exe`)
- `product_module` 由 adapter 子类声明(见 §15.4)
- `--input` 后跟**一行 JSON 字符串**(用 `json.dumps(payload, ensure_ascii=False)` 序列化)
- `--json` 必填 —— 决定走 envelope 输出而不是人类可读模式
- `cwd` 设为产品仓库根目录
- `PYTHONPATH` 自动追加产品 `src/` 目录(adapter 负责)

### 15.3 输出 envelope

产品 stdout **必须**是合法 UTF-8 JSON,二选一:

**形态 A · 对象包 findings**(推荐):
```json
{
  "findings": [
    {"id": "<uuid-or-product-id>", "severity": "<info|low|medium|high|critical>",
     "confidence": <0.0-1.0>, "title": "<一句话>", ...其他 Finding 字段...}
  ]
}
```

**形态 B · 顶层数组**:
```json
[{"id": "...", "severity": "...", ...}]
```

**字段兼容性**(由 `JSONSubprocessAdapter` 自动归一化):
- 缺 `id` → 用空串(`Finding.from_dict` 后续会自动填)
- 缺 `source` → **强制注入**为 adapter 自己声明的 `FindingSource` 值
- 缺 `severity` → 默认 `"medium"`
- 缺 `confidence` → 默认 `0.5`
- 缺 `title` → 默认 `"Untitled finding"`

**其他允许字段**(`Finding` schema 全部支持):`host` / `cve` / `description` / `ts` / `evidence` (list) / `related` (list) / `tags` (list) / `metadata` (dict)。

**未知字段**:`Finding.from_dict` 容忍,忽略不抛错(§9.6 承诺)。

### 15.5 错误行为契约

- **退出码 ≠ 0** → adapter 抛 `ProductCLIError`,**不**自动重试
- **stdout 不是合法 JSON** → adapter 抛 `ProductCLIError("CLI emitted invalid JSON")`
- **envelope 顶层不是 object / array** → adapter 抛 `ProductCLIError("findings must be a list")`
- **单个 finding 不是 dict** → adapter 抛 `ProductCLIError("finding must be an object")`
- **stderr 内容** → 错误消息里透传(stderr 写人类可读诊断)
- **超时** → 当前**不**强约束超时;v0.7 加 `timeout=30s` 默认

**期望 stdout**(UTF-8 JSON,带换行):

```json
{"findings": [{"id": "002-vuln-0001", "source": "002", "severity": "high", "confidence": 0.9, "title": "CVE-2024-1234 on 10.0.0.1", "host": "10.0.0.1", "cve": "CVE-2024-1234"}]}
```

**期望 stderr**(人类可读,可选;只在 warning/error 时写):

```
[002-vuln] scanned 1 row, 1 finding
[002-vuln] CVE-2024-1234 mapped from Qualys QID-12345
```

**adapter 拿到 stdout 后做的事**:

1. `json.loads(stdout)` → dict `{"findings": [...]}`(或 list)
2. 对每条 finding:`Finding.from_dict(d)` → 容忍未知字段
3. 强制注入 `source=FindingSource.VULN`(若产品忘记填)
4. `await registry.add(finding)`
5. 触发 correlation rules

### 15.5.3 CI 烟雾测试脚本

放到 `000shared-integration/tests/integration/test_cli_envelope_smoke.py`,6 个产品 × 1 个 smoke test:

```python
import json, subprocess
import pytest

PRODUCTS = [
    ("001AI-SOC-Agent", "ai_soc_agent.cli", {"source": "sshd", "events": []}),
    ("002AI-Vulnerability-Agent", "ai_vuln_agent.cli", {"scanner": "qualys", "csv_content": ""}),
    # ... 其余 4 个
]

@pytest.mark.parametrize("rel,module,payload", PRODUCTS)
def test_cli_emits_valid_envelope(rel, module, payload):
    proc = subprocess.run(
        ["python", "-m", module, "scan", "--input", json.dumps(payload), "--json"],
        capture_output=True, text=True, cwd=ROOT / rel, timeout=60,
    )
    # 子进程可能因为依赖未装 RC!=0,但只要 stdout 是合法 JSON envelope 就 PASS
    if proc.stdout.strip():
        env = json.loads(proc.stdout)
        findings = env["findings"] if isinstance(env, dict) else env
        assert isinstance(findings, list)
```

### 15.6 adapter 端实现要点

adapter 必须:

1. `source: ClassVar[FindingSource]` — 声明产品身份
2. `module: ClassVar[str]` — 上面表格里的 module 名
3. `product_id: ClassVar[str]` — 上面表格里的 product_id(如 `001-soc`)
4. 继承 `JSONSubprocessAdapter`,**不**重写 `scan` / `health`(除非有特殊理由)
5. `__init__(cli_path: Path)` 收产品仓库根目录

## 16. 加法能力：不可信 prompt 内容边界

`shared_llm_core.untrusted` 提供三个独立 helper 和一个 system prompt 常量：

- `wrap_untrusted(content, *, kind)`：把外部日志、源码、反汇编或固件字符串标成待分析数据；
- `scrub_control_sequences(content)`：移除终端转义、不可见格式与解析控制字符；
- `truncate_evidence(content, *, max_chars)`：限制证据长度并返回截断标记；
- `INJECTION_GUARD_SYSTEM_PROMPT`：声明定界块是数据而非指令。

这是 v0.5 冻结后的**纯加法能力**。它不修改 §7–§10 的任何签名，也不自动改变既有
调用方。产品只有在显式导入、拼接 guard system message 并调用 `wrap_untrusted` 后才
启用该边界；未采用的产品行为保持不变。

# RFC-001: shared-llm-core v0.5 freeze

- **Status**: Accepted
- **Decision date**: 2026-07-25
- **Owners**: longyuanai maintainers
- **Applies to**: `shared-llm-core` §1-§10 and the §15 CLI Envelope addendum

## Summary

The longyuanai v0.5 API surface is frozen. The six product repositories have adopted
the shared Finding and gateway contracts, their real CLI envelopes pass subprocess
smoke tests, and the core suite has no regression.

This RFC freezes interfaces; it does not claim production readiness. Authentication,
persistent storage, retry policy, multi-tenancy, and 30 days of production traffic
remain later-version work.

## Decision

The following public surfaces are compatibility commitments:

1. §1-§6 v0.1 symbols remain unchanged.
2. §7 `MultiAgentOrchestrator`, roles, mission context, and results.
3. §8 `Rule`, `RuleRegistry`, `RuleContext`, and `RuleEngine`.
4. §9 `Finding`, `FindingSource`, and `FindingSeverity`.
5. §10 `FindingRegistry`, `ProductAdapter`, correlations, and HTTP gateway routes.
6. §15 product CLI invocation and JSON envelope normalization.

The canonical definitions are:

- `docs/v0.5-contract.md`
- source-level API cheat sheets in `finding.py`, `multi_agent.py`, `rule_engine.py`,
  and `gateway.py`
- executable examples in `tests/test_contract_examples.py`
- cross-repository smoke tests in `tests/integration/test_cli_envelope_smoke.py`

## Compatibility rules

### Allowed in v0.5.x

- Bug fixes that preserve documented behavior.
- Documentation and test improvements.
- New optional fields with backward-compatible defaults.
- New enum-independent helper APIs that do not alter existing signatures.
- Performance and security hardening with equivalent observable behavior.

### Not allowed in v0.5.x

- Removing or renaming a public symbol, field, enum value, route, or envelope key.
- Reordering or changing required positional parameters.
- Changing `Finding.to_dict()` field semantics or rejecting previously accepted
  `Finding.from_dict()` input.
- Changing the six `FindingSource` values.
- Replacing the §15 subprocess protocol without a compatibility path.
- Adding mandatory product dependencies to `shared-llm-core`.

A breaking change requires a new RFC, a migration guide, and a major-version boundary.

## §15 CLI envelope commitment

Each product must accept:

```text
<absolute-python> -m <product-module> scan --input <one-line-json> --json
```

The process must exit with code zero for valid input and emit UTF-8 JSON whose
`findings` value is a list. The integration adapter owns default injection for missing
`id`, `source`, `severity`, `confidence`, and `title`.

Products remain isolated subprocesses. Cross-product deep imports are not part of the
contract.

## Known limitations

- `FindingRegistry` is process-local and in-memory.
- SSE does not replay missed events.
- Product adapters do not yet define a contract-level retry or timeout policy.
- Gateway authentication and tenant isolation are not implemented.
- Automated GitHub Actions orchestration is tracked separately by `007-CI`.
- Web Dashboard delivery is independent of this API freeze.

These limitations are accepted for the local/offline v0.5 demonstration scope.

## Rollback

The freeze adds tests and documentation without a data migration. Rollback is an
ordinary Git revert of the relevant 005-FINAL commit. Existing §1-§10 runtime behavior
must not be rolled back independently of its public contract.

## Exit criteria toward v1.0

v1.0 remains gated by:

1. all seven longyuanai products reaching v1.0,
2. the IntegrationGateway carrying real production traffic for 30 days,
3. authentication and persistence decisions being captured in follow-up RFCs, and
4. automated CI enforcing the frozen contract.

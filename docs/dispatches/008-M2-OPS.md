# 008-M2-OPS：M2 运维门禁收口

## 1. 目标

用可复核证据关闭 M2 剩余的两个门禁：PostgreSQL 备份/恢复实演，以及真实 PostgreSQL 并发幂等验证。

本派活默认使用本地 Docker PostgreSQL 或一次性测试数据库；不对生产数据执行恢复、删库或压力测试。

## 2. 范围

允许修改：

- `000shared-integration/tests/`（仅在现有测试确有证据缺口时）
- `000shared-integration/src/shared_integration/scripts/seed_e2e.py`（仅限演练直接暴露的 seed 兼容修复）
- `000shared-integration/DEPLOYMENT.md`
- `000shared-integration/docs/architecture.md`
- `000shared-integration/PHASE-2.md`
- `000shared-integration/AUDIT/008-M2-OPS.md`

不得修改：

- 六个产品仓及 `web-ui` 的业务代码
- `000shared-llm-core` 冻结契约和 `suite-lock.yml`
- `003AI Agent安全靶场` 的现有未提交修改
- 任何真实凭据、连接串、Token 或客户数据

## 3. ISSUE

### OPS-BACKUP-001：备份/恢复实演

1. 准备一次性 PostgreSQL 源库和独立恢复库。
2. 按 `000shared-integration/DEPLOYMENT.md` 执行迁移与测试数据准备。
3. 使用 `pg_dump` 生成备份，计算 SHA-256。
4. 使用 `pg_restore` 恢复到空目标库；不得覆盖源库。
5. 比对 schema revision、关键表行数和代表性数据。
6. 记录备份大小、校验和、恢复耗时、PostgreSQL/工具版本和日期。

### OPS-CONCURRENCY-001：PostgreSQL 并发门禁

1. 设置一次性 `INTEGRATION_TEST_POSTGRES_URL`，不得把值写入仓库或日志。
2. 运行 `tests/test_postgres_integration.py`，包括并发 idempotency claim 与 finding dedup 测试。
3. 至少连续运行 3 次；每次都必须通过，且没有死锁、唯一性冲突泄漏或重复 Finding。
4. 如现有测试暴露实现缺陷，先写失败回归测试，再做最小修复；若只是环境问题，不改业务代码掩盖它。

### DOC-OPS-001：证据与状态同步

1. 写 `000shared-integration/AUDIT/008-M2-OPS.md`。
2. 更新 `docs/architecture.md` 和 `PHASE-2.md` 的 M2 状态。
3. 报告环境类型、命令、结果、证据位置、偏差和剩余风险；敏感值统一写成 `<redacted>`。

### OPS-SEED-001：演练暴露的最小修复

若空迁移库或真实 PostgreSQL seed 失败，仅修复直接阻断演练的 schema 漂移，并补回归测试；不得借机重构业务代码。

## 4. 验证命令

PowerShell 示例；Python 必须使用项目约定的绝对路径：

```powershell
$env:PYTHONPATH = "src;../000shared-llm-core/src"
$env:INTEGRATION_TEST_POSTGRES_URL = "<temporary-postgres-url>"
& 'C:\Users\15072\AppData\Local\Programs\Python\Python314\python.exe' -m pytest --basetemp=C:/pytest-tmp/ -o addopts= tests/test_postgres_integration.py -q
```

完成专项验证后，再运行项目全量测试和 IntegrationGateway smoke：

```powershell
& 'C:\Users\15072\AppData\Local\Programs\Python\Python314\python.exe' -m pytest --basetemp=C:/pytest-tmp/ -o addopts= tests -q
& 'C:\Users\15072\AppData\Local\Programs\Python\Python314\python.exe' -m shared_integration.admin_cli --help
```

`scripts/inspect_worker_return.py --project` 当前只识别 6 个产品 worker，不识别 `000shared-integration`；本派活以全量 pytest、admin CLI 和临时 Gateway `/livez` 为等价验收，并在报告中注明。

## 5. 验收标准

- 代码修复、运维证据和阶段状态分别形成清晰 commit；没有代码修复时不制造空 commit。
- 备份可恢复到独立空库，校验和与行数证据齐全。
- PostgreSQL 集成测试连续 3 次通过。
- 项目全量 pytest、admin CLI 与 Gateway `/livez` smoke 通过。
- 审计报告不含凭据，且能让另一位执行者复现实验。
- 未触碰范围外仓库和 `003AI Agent安全靶场` 的受保护修改。
